# Aeternum.WorldGen

Процедурная симуляция мира без сценария: всё, что происходит, — следствие
взаимодействия систем, а не заранее прописанных событий. Персонажи рождаются,
взрослеют, работают, женятся, изменяют, заводят детей (в браке и вне его) и
умирают; из семей складываются династии, из поселений — государства.

Мир держится на нескольких слоях, каждый следующий опирается на данные
предыдущего, а не заводит собственные:

  - Демография — возраст, браки, разводы, романы на стороне, смерть,
    сиротство, опека, незаконнорождённые, наследование престола по обычаю
    культуры.
  - География — координаты поселений задают климат (широтный пояс),
    рельеф (низины/холмы/горы, тем же шумом, что и климат) и погоду года
    (общий для мира блуждающий фон); из рельефа же выводятся месторождения.
  - Экономика — производство и потребление еды и материалов, склады и порча,
    мастерские и гильдии, торговля внутри государства и с внешним рынком,
    постройки (дома, больницы, школы, мастерские, стены) и их ветшание.
  - Общество — сословия (выводятся из положения, не хранятся отдельно),
    духовенство и его влияние на расколы веры, языковой барьер, дружба и
    вражда между персонажами.
  - Политика — государства возникают эмерджентно (одна династия доминирует
    в нескольких поселениях), войны, союзы, вассалитет, восстания, заговоры,
    гильдии и цехи, войско как единая величина с ценой и силой, двор со
    светскими должностями.
  - История — хроника мира и хроника отдельной короны, биографии заметных
    личностей, ASCII-карта, знания и эпохи.

Ключевой принцип: новая механика встраивается в то, что уже есть в данных,
а не добавляет сущности ради эффекта. Если что-то можно вывести из
существующих полей (координаты, профессия, стаж, семья), отдельное поле
для этого не заводится.

## Запуск

Консольное приложение на .NET 10. В папке два проекта (игра и тесты), поэтому
`dotnet build`/`run`/`test` без аргументов используют решение `Aeternum.slnx`.

    dotnet run --years=1000 --settlements=10 --population=90 --seed=42 --quiet
    dotnet test

Аргументы запуска — все необязательны (см. Settings/`ProjectSettings.cs`):

    --years=N        лет симуляции (по умолчанию 100)
    --settlements=N  стартовых поселений (по умолчанию 3)
    --population=N   стартовых жителей (по умолчанию 30)
    --seed=N         зерно мира; без него — случайное (печатается при запуске,
                      так что понравившийся мир всегда можно повторить)
    --quiet          не печатать погодовой лог событий (на долгих прогонах
                      читать его всё равно нельзя — смотрят по итогам)
    --help           показать эту справку

## Архитектура

  - Мир — один объект World (Core/`World.cs`), передаётся во все системы.
    Системы — статические классы с методом `Process(World)`, без собственного
    состояния между вызовами.
  - Год обрабатывается фиксированным, пронумерованным порядком систем —
    Simulation/`YearProcessor.cs`. Это единственный источник истины насчёт
    порядка: при вставке новой системы нумерация комментариев сдвигается.
  - Вся случайность идёт через один генератор с зерном (Core/`Rng.cs`) — мир
    с известным зерном воспроизводится в точности, что и позволяет измерять
    "было/стало" при подборе порогов.
  - Не каждая система стоит в пайплайне сама по себе: часть — чистые функции,
    которые считают что-то по требованию (климат, рельеф, сословие, гильдия,
    духовный сан) и вызываются из систем-потребителей или из отчётов, а не
    крутятся каждый год отдельным шагом.
  - Отчётные системы возвращают данные (DTO с ссылками на настоящие объекты),
    а не готовый текст — русский текст строит только `Program.cs`. Это одно и
    то же разделение, что уже применено к сохранению: `SaveData` — плоские DTO
    с Id-ссылками, а не сами объекты.

## Карта проекта

    Core/          — мировое состояние, генератор случайности, движок тика
    Models/        — данные мира: персонаж, семья, династия, государство,
                     поселение, культура, религия, язык, настройки, DTO
                     отчётов, перечисления (Models/Enums)
    Systems/       — вся логика симуляции: ~55 статических классов,
                     от старения до дипломатии
    Generators/    — фабрики стартового контента (персонажи, культуры,
                     религии, языки, поселения)
    Data/          — JSON с игровым контентом (имена, профессии, культуры,
                     религии, названия поселений) и его загрузчик
    Events/        — WorldEvent — единица лога событий мира
    Simulation/    — YearProcessor — порядок систем внутри одного года
    Settings/      — параметры запуска (не путать с WorldSettings — те
                     про сам мир, эти про то, как его запустили)
    Save/          — сохранение и загрузка мира в JSON (для продолжения игры)
    Export/        — отдельный, более плоский снимок мира для клиента-
                     отрисовщика (Godot) — не то же самое, что Save
    Program.cs     — точка входа: генерация мира, симуляция, вся консольная
                     печать отчётов, save/load
    Aeternum.WorldGen.Tests — xUnit-тесты

Во всех папках, кроме `Program.cs` и корня, лежит свой README с более
подробным описанием содержимого.

## Проверка

CI (.github/workflows/ci.yml) гоняет build+test на каждый push/PR в main.
Локально перед коммитом: `dotnet build Aeternum.slnx`, `dotnet test`, и для
новых балансных порогов — живой прогон на 1000 лет с последующей проверкой
на нескольких зёрнах (мутационная проверка новых тестов — отдельным шагом).
