# Save

Сохранение и загрузка мира в JSON — для продолжения игры, не для отрисовки
(за тем — см. ../Export/README.md, это разные форматы с разными причинами
меняться).

  - `SaveData.cs` — плоское представление World: персонажи, семьи, династии,
    поселения, культуры, языки, религии, государства, торговые пути и
    события мира — каждый как отдельный *Data-класс, ссылающийся на другие
    по Id (`MotherId`, `CurrentFamilyId`, `RulerId`, `KingdomIds` и т.д.), а не по
    прямой ссылке на объект. Без этого сериализация уткнулась бы в циклы
    (`Character.Mother` ↔ `Family.Father` ↔ `Family.Children` ↔ Character…).
  - `SaveSystem.cs` — Serialize/Deserialize работают со строкой, а не с
    файлом: файловый ввод-вывод (File.*) не зашит внутрь, поэтому и консоль,
    и будущий Godot-клиент со своим `FileAccess` могут использовать одну и ту
    же логику. Save/Load — тонкие обёртки поверх Serialize/Deserialize,
    добавляющие только чтение/запись файла.

Загрузка — многофазная реконструкция: сперва создаются все объекты без
перекрёстных ссылок (только их собственные поля), затем отдельным проходом
проставляются ссылки, которые могут указывать на ещё не созданные на первом
проходе объекты (например, `Kingdom.AlliedKingdoms` — государство ссылается
само на себя через список других государств). Тот же порядок забот, что и
при разборе любого графа объектов из плоского представления: сначала все
узлы, потом все рёбра.
